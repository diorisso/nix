# AGENTS

Use this playbook whenever you extend the `nixos` flake or the bundled Home Manager profile. It captures commands, expectations, and guardrails tailored to this host.

## Stack Orientation
- Hostname: `nixos`; flakes are enabled via `nix.settings.experimental-features = [ "nix-command" "flakes" ];`.
- Key modules: `configuration.nix` (system), `home.nix` (Home Manager), `hardware-configuration.nix` (generated, do not hand-edit), `flake.nix` (inputs + outputs).
- Desktop stack: system-level Cinnamon for display manager fallback plus Hyprland + Waybar + Hyprpaper/PipeWire from Home Manager.
- Custom tooling: multiple `writeShellScriptBin` helpers for wallpapers, audio routing, screenshots, and shaders; each script expects Hyprland/Wayland utilities from `pkgs`.
- Unfree packages are allowed at both system and user layers; `inputs.zen-browser` is consumed through `environment.systemPackages`.

## File-by-File Notes
- `flake.nix`: declares inputs and produces `nixosConfigurations.nixos`. Keep descriptions short, and always pass new inputs through `specialArgs` so both system and Home Manager modules can see them.
- `configuration.nix`: owns bootloader, networking, locales, system services, and bridges Home Manager. Match the existing section ordering and keep related settings grouped with blank lines.
- `home.nix`: everything user-scoped lives here—packages, scripts, config files, Hyprland, Waybar. Favor extending the current attribute sets over creating duplicates.
- `hardware-configuration.nix`: generated by `nixos-generate-config`; never edit manually. Instead, re-run the generator if hardware changes.
- `.codex` marker: empty file marking agent ownership. Leave it untouched.
- There are no hidden modules elsewhere; if you need to split files, update `imports` explicitly.

## Command Playbook
- Inspect the flake graph any time you touch `flake.nix`:
  ```bash
  nix flake show
  ```
- Build + activate the full system (includes Home Manager because it is a module):
  ```bash
  sudo nixos-rebuild switch --flake .#nixos
  ```
- Dry-run activations when you are unsure about side effects:
  ```bash
  sudo nixos-rebuild dry-activate --flake .#nixos
  ```
- Fast safety pass before merging: evaluate without activating.
  ```bash
  nix build .#nixosConfigurations.nixos.config.system.build.toplevel
  ```
- Single change smoke-test (closest analogue to a “single test”): build only the Hyprland-aware host derivation; inspect `./result` before switching.
  ```bash
  nix build .#nixosConfigurations.nixos
  ls -l result
  ```
- Home-only verification (no reboot) still goes through `nixos-rebuild test` because Home Manager is imported as a module:
  ```bash
  sudo nixos-rebuild test --flake .#nixos
  ```
- Update inputs responsibly. Refresh just nixpkgs or a specific input to avoid churn.
  ```bash
  nix flake lock --update-input nixpkgs
  nix flake lock --update-input zen-browser
  ```

## Option Discovery & Diffing
- Query current option values through NixOS tooling before making assumptions.
  ```bash
  nixos-option services.xserver.desktopManager.cinnamon.enable
  ```
- For Home Manager attributes, drop into a shell with `home-manager help` or evaluate via `nix eval`:
  ```bash
  nix eval .#nixosConfigurations.nixos.config.programs.waybar.enable
  ```
- Compare generations when debugging regressions:
  ```bash
  sudo nix-env -p /nix/var/nix/profiles/system --list-generations
  ```
- Use `nix profile history` sparingly; most changes land through flakes, so generation diffs are usually more helpful.

## Format & Lint
- Nix formatting is manual—spawn `alejandra` or `nixpkgs-fmt` ad hoc.
  ```bash
  nix shell nixpkgs#alejandra -c alejandra configuration.nix home.nix flake.nix
  ```
- For scripted `''` blocks, lint with `shellcheck` after copying the snippet into a temp file or piping.
  ```bash
  nix shell nixpkgs#shellcheck -c "pbpaste | shellcheck -s bash"
  ```
- Waybar CSS lives inside `home.file`. Validate with `npx stylelint` only if you extract the CSS; keep inline styles minimal and consistent.
- There are no automated tests beyond `nix build`/`nixos-rebuild`; always run at least one build command before opening a PR.

## Nix Expression Style
- Two-space indentation everywhere; attrsets open on the same line as `{ config, pkgs, ... }:` and close with `};` aligned to column 1.
- Keep option groups separated by blank lines: boot, hardware, networking, locale, services, users, programs, packages, system.
- Lists should be vertical, one element per line, trailing semicolon immediately after the closing bracket (see `environment.systemPackages`).
- Prefer explicit attribute references (`pkgs.hyprland`) over `with pkgs;` unless you assign to `home.packages` or a short package list; the existing files already switch to `with pkgs;` before large vectors.
- Multi-line strings must use `''` heredocs; keep indentation consistent with the attrset and avoid inline tabs.
- Imports belong in the `imports = [ ... ];` block; keep local files before module paths, and never mutate `hardware-configuration.nix` manually.
- When adding new flake inputs, mirror the pattern used for `home-manager` and `zen-browser`: follow `nixpkgs` for compatibility and expose via `specialArgs`/`extraSpecialArgs`.

## Home Manager Conventions
- User scope lives entirely inside `home.nix`; prefer `home.packages` for user apps and reserve `environment.systemPackages` for global tools.
- `home.sessionVariables` is the right place for Node/npm prefixes—append to `home.sessionPath` instead of modifying `/etc/profile`.
- Cursor and theme settings are centralized under `home.pointerCursor`; reuse those env vars (`XCURSOR_THEME`, `HYPRCURSOR_THEME`) in Hyprland’s `env` list when necessary.
- All `home.file."…".text` entries should be deterministic; keep CSS, TOML, and GLSL content self-contained with clear spacing and high-level comments only when truly needed.
- Directory creation belongs in `home.activation` with `lib.hm.dag.entryAfter [ "writeBoundary" ] ''…''`; keep activation steps idempotent.
- Program modules such as `programs.git`, `programs.waybar`, and `wayland.windowManager.hyprland` are already enabled—extend their existing attrsets instead of redefining modules elsewhere.

## Shell Script Patterns
- Every `writeShellScriptBin` helper starts with a shebang referencing `${pkgs.bash}/bin/bash` and immediately sets `set -euo pipefail` (or at minimum `set -euo pipefail` unless the script is trivial). Follow that template.
- Depend on store paths, not PATH lookups: `${pkgs.hyprland}/bin/hyprctl`, `${pkgs.pulseaudio}/bin/pactl`, `${pkgs.coreutils}/bin/date`, etc.
- Quote every variable (`"$dir"`, `"$monitor"`) and guard for empties; scripts here exit early when optional commands (e.g., `notify-send`) are missing, so use `command -v … >/dev/null 2>&1` before calling.
- Use `mapfile -t` for sink arrays, prefer `printf` over `echo -e`, and trim strings manually like `audio-output-status` does.
- When ignoring failures, do it explicitly with `|| true` beside the risky call (see hyprpaper unload loop) so future readers know the failure is intentional.

## Desktop Stack Notes
- LightDM is the display manager, but Hyprland is started by Home Manager; keep their settings in sync (keyboard layout, cursor theme).
- Monitor definitions live in `wayland.windowManager.hyprland.settings.monitor`; maintain the `gaps`, `animations`, and `bind` sections grouped exactly as shown (navigation, movement, resize, workspace switching).
- Waybar config is embedded JSON under `programs.waybar.settings`. Add modules by extending `modules-left/center/right` arrays and defining accompanying objects; mirror the existing `custom/nightlight` pattern for new `custom/*` blocks.
- Waybar style lives in a single CSS string; maintain the clean type stack (JetBrainsMono fallback chain) and consistent RGBA palette when adding selectors.
- Nightlight and audio scripts interact via Hyprshade and PulseAudio; when adding new shaders or sinks expose toggles under `custom/*` modules to stay coherent.
- Wallpapers are handled by the `random-wallpaper` service; any new wallpaper logic should continue storing assets inside `$HOME/Wallpapers` and respect hyprpaper preload loops.

## Packages & Dependencies
- System packages currently include `vim`, `neovim`, `ghostty`, `steam`, and `inputs.zen-browser`. Keep GUI apps user-scoped unless they must run before login.
- User packages install `git`, `nodejs`, `opencode`, Hypr utilities, and screenshot tools; add related CLI utilities alongside them for coherence.
- When referencing new flakes or overlays, surface them through `inputs` and wire them either in `environment.systemPackages` or via modules (e.g., `programs.hyprland`).

## Troubleshooting & Observability
- `journalctl -b` remains the authoritative place for systemd service failures; pair with `sudo nixos-rebuild test` to iterate quickly.
- Hyprland issues: inspect `~/.local/share/hypr/hyprland.log` and `WAYBAR_LOG_LEVEL=debug waybar` when debugging modules.
- PipeWire/Audio: `systemctl --user status pipewire` and `pactl list sinks short` mirror what the helper scripts expect—confirm output names before shipping script tweaks.
- Wallpaper + hyprpaper problems: `hyprctl hyprpaper listloaded` verifies that preload loops succeeded before you blame Waybar buttons.
- If `nixos-rebuild` fails evaluation, re-run with `--show-trace` for full stack traces.

## Error Handling & Defaults
- Locale is mixed (`en_US` default, `pt_BR` extras). Do not drop the Brazilian locales when altering i18n settings.
- Keep `security.rtkit.enable = true` whenever PipeWire is active; audio helpers assume RTKit.
- Preserve `services.pipewire`’s 32-bit ALSA support and `hardware.graphics.enable32Bit` if you expect Steam or Proton to keep working.
- Any new services should copy the pattern of enabling modules plus providing per-service configs inside the same attrset, minimizing scattered state.

## State & Secrets
- `system.stateVersion` and `home.stateVersion` are pinned to `25.11`; bump only when you intentionally adopt new defaults.
- User-specific env vars (npm prefix, cursor theme) already live under `home.*`; resist the urge to set them under `/etc` to keep declarative parity.
- Secrets do not belong in this repo; prefer `age`/`sops` modules or hardware key stores if you need credentials.
- For npm, stick with `$HOME/.npm-global` and the provided `home.sessionPath` extension.
- Keep `home.activation` steps idempotent—avoid touching mutable directories outside `$HOME`.

## Cursor & Copilot Guidance
- `.cursor/` and `.github/copilot-instructions.md` do not exist in this repository. There are no extra editor rules to follow beyond what is captured here.

## Pre-PR Checklist
- Run one of the build commands (`nix build` or `sudo nixos-rebuild test`) and state which one you used in the PR body.
- Format touched Nix files with `alejandra` (or similar) and sanity-check embedded shell/CSS snippets.
- Verify `flake.lock` diffs are intentional; avoid incidental mass upgrades unless requested.
- Keep secrets out of the repo—activation scripts already read everything from the store or `$HOME`.
- Never modify `hardware-configuration.nix` by hand; regenerate via `sudo nixos-generate-config --show-hardware-config` if hardware changes.

## Working Tree Hygiene
- You may be in a dirty git worktree; never revert existing changes you did not make unless explicitly requested.
- Skip `git commit` unless the user asks for one—deliver patches or files instead.
- Avoid destructive commands such as `git reset --hard`; favor targeted edits and document any manual steps you had to take.

Stay disciplined with these patterns and every future agent will be able to iterate safely.
